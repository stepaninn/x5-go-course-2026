# Занятие 9 — контракт сервиса заказов

В заготовке уже работают создание и чтение заказа. На практике нужно описать их контракт через swaggo и открыть Swagger UI. Код бизнес-логики переписывать не требуется.

Открыть в IDE именно эту папку `student`. Здесь свой Go-модуль. Требуется Go 1.22 или новее.

```bash
go mod download
go test ./...
go run ./cmd/orders
```

Сервер слушает `127.0.0.1:8080`. Остановить его можно Ctrl+C. Если там уже запущено демонстрационное приложение преподавателя, сначала остановить его.

Работающие маршруты:

| Запрос | Результат |
|---|---|
| `GET /api/v1/status` | `200`, `{"status":"ok"}` |
| `POST /api/v1/orders` с `{"customer":"Алиса"}` | `201`, JSON заказа и заголовок `Location` |
| `GET /api/v1/orders/1` после создания | `200`, JSON заказа |
| `GET /api/v1/orders/abc` | `400`, `INVALID_ID` |
| `GET /api/v1/orders/999` | `404`, `ORDER_NOT_FOUND` |

У каждого заказа есть `id`, `customer`, `status`. При создании сервер присваивает `status: "new"`. Данные хранятся в памяти и исчезают после перезапуска. Повторные заказы одного клиента разрешены.

Тело POST должно содержать ровно один JSON-объект с полем `customer`, максимум 1024 байта. Требуется `Content-Type: application/json`; параметры вроде `charset=utf-8` допускаются. Пустое или пробельное имя, неизвестные поля, `null` и лишнее JSON-значение отвергаются. Ошибки API под `/api/v1/` имеют формат `{"error":"описание","code":"СТАБИЛЬНЫЙ_КОД"}`. Неизвестный маршрут возвращает `404 ROUTE_NOT_FOUND`, неподдерживаемый метод — `405 METHOD_NOT_ALLOWED` с заголовком `Allow`.

Файлы для практики:

- `cmd/orders/main.go`: общие аннотации API.
- `internal/httpapi/handlers.go`: аннотации конкретных операций.
- `internal/httpapi/dto.go`: типы тела запроса и ответов.
- `internal/httpapi/routes.go`: маршруты и место для подключения UI.
- `generate.go`: команда генерации закреплённым `swag v1.16.6`.
- `requests.http`: запросы для ручной проверки.

В стартовом проекте нет аннотаций операций, каталога `docs` и маршрута Swagger UI. Это ожидаемое состояние. Сначала выполнить [TASKS.md](TASKS.md). После добавления аннотаций:

```bash
go generate ./...
```

Команда создаст `docs/docs.go`, `docs/swagger.json` и `docs/swagger.yaml`. После подключения UI проверить сборку и перезапустить сервер. При первом запуске генератора нужен интернет для загрузки его зависимостей. Версии генератора и библиотек закреплены, обновлять их во время практики не требуется.
