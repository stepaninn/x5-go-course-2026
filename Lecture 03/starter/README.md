# Starter СР-1

## Описание алгоритма

Алгоритм принимает на вход срез продаж и выдает отчет, в котором посчитана общая стоимость товаров в копейках, число проданных товаров, выручка по категориям товаров и самый продаваемый товар

AnalyzeSales начинается с инициализации отчета и мапы внутри него. Дальше задается мапа для товаров, чтобы можно было корректно посчитать количество проданных товаров (в случае если продастся 2 кофе, 3 чая и еще раз 2 кофе, то по итогу лидером будет кофе, так как мы смотрим на все продажи)

В цикле мы проходимся по срезу и пропускаем отменённые продажи и считаем
некорректные записи

Для неотмененных и корректных товаров мы обновляем общую выручку и число проданных товаров, также считаем выручку по категориям и количество единиц каждого товара

Затем проходим мапу количеств и выбираем самый продаваемый товар. При равенстве не забываем выбирать меньшее лексикографически название

Исходный срез по итогам работы алгоритма не меняется

### Оценка сложности

Пусть n -- число записей, p -- число уникальных товаров, c -- число уникальных категорий. p и c учитываются только для корректных и неотмененных продаж

При средней сложности операций O(1) для мапы время работы алгоритма будет составлять O(n + p) = O(n). Дополнительная память будет использоваться только для мапы количества товаров -- O(p + c) 

**Итоговая сложность времени алгоритма O(n)**

## Задание

Реализуйте анализатор продаж:

```go
func AnalyzeSales(sales []Sale) Report
```

Для каждой продажи известны товар, категория, количество, цена за единицу в
копейках и признак отмены. Функция должна:

- рассчитать общую выручку в копейках;
- посчитать число проданных единиц;
- собрать выручку по категориям;
- определить самый продаваемый товар по количеству единиц;
- посчитать некорректные записи;
- не изменять исходный срез.

## Правила

- Запись некорректна, если товар или категория пусты, количество не положительно
  либо цена не положительна.
- Некорректная запись не участвует в остальных расчётах и увеличивает
  `InvalidSales`.
- Отменённая продажа пропускается раньше валидации: она не входит в отчёт и не
  считается некорректной.
- При равном количестве проданных единиц лидером становится лексикографически
  меньшее название товара.
- Для пустого входа возвращается отчёт с нулевыми значениями и созданной пустой
  `RevenueByCategory`.
- Используйте только структуры, срезы, `map`, условия, циклы и функции.
  Интерфейсы, горутины и сторонние библиотеки не нужны.
